## Day 2（2h）— SSE 解析器（TS）

**目标**：写一个**不依赖任何库**的 SSE 解析器，这是整周最容易被低估的部分。

**任务**

- [x] `ts/src/sse.ts`：实现 `createSSEParser()`，输入文本 chunk，输出事件数组
- [x] 必须按状态机处理：
  - 按行切分，**保留最后一行残留**（半包）
  - 一个 chunk 可能含多个事件（粘包）
  - `\r\n` 与 `\n` 都要支持
  - `data: [DONE]` 作为终止信号，不当作 JSON 解析
  - 以 `:` 开头的行是注释（keep-alive），丢弃
- [x] 用**手工构造的畸形 chunk** 写 8 条单测（不用真网络）：
  - 事件被从中间切断
  - 一个 chunk 内 3 个完整事件
  - `data:` 后无空格
  - 空 data 行
- [x] 接上真实接口，流式打印 `choices[0].delta.content`

**验收**

- [x] 8 条单测全绿，且**没有一个**是真网络请求
- [x] 真接口下中文/emoji 不出现乱码（说明 UTF-8 边界处理正确）
- [x] 能解释：为什么不能在 chunk 到达时直接 `split("\n\n")` 就完事

**坑点提醒**：UTF-8 多字节字符可能被 chunk 边界切断，必须用 `TextDecoder({stream: true})`，不能用 `buf.toString()`。

## Day 4（2.5h）— 增量 tool_calls 拼接（本周核心）

**目标**：这是 W1 唯一会被后续所有周复用的组件，必须写对。

**任务**

- [ ] `ts/src/tool-accum.ts`：`ToolCallAccumulator`
  - 首块含 `index` + `id` + `function.name` + **空** `arguments`
  - 后续块通常只有 `index` + `arguments` 片段，**没有 id**
  - **必须用 `index` 做分桶 key，不能只用 id**（用 id 会丢掉后续所有片段）
  - 多个工具并行调用时，片段会交错到达
- [ ] 累积完成后再 `JSON.parse`，不能在片段中途 parse
- [ ] 写单测：2 个工具并行、args 在 5 个分片里、某分片 `arguments` 为空串、分片交错
- [ ] Python 侧同步实现
- [ ] 接真实接口，发一个"同时查两个城市天气"的请求，验证两个 tool_call 都能拼完整

**验收**

- [ ] 并行双工具场景下，两个 arguments 都能 `JSON.parse` 成功
- [ ] 单测覆盖"第二个工具的首块不带 id"的情况
- [ ] 能解释：为什么 `finish_reason` 到达时不能立即认为 arguments 已完整

**坑点提醒**：`finish_reason` 在 `choices[0]` 上，但**不代表参数收完**——某些网关会在 `finish_reason` 之后再补发 usage-only chunk，也有实现把最后一段 arguments 放在 finish 之后的 chunk 里。判定"完整"的唯一标准是：**流已结束（收到 `[DONE]` 或连接正常关闭）+ JSON.parse 成功**。

## Day 6（2h）— 故障形态实测

**目标**：拿到 4 类故障的**真实**响应样本，这是后面写重试策略的依据。

**任务**

- [x] `ts/src/probe.ts` 依次制造：
  - 429：连续快速请求触发限流，记录 `Retry-After` 头是否存在
    —— **未复现**：12 / 30 并发全部 200，且无任何限流头
  - 5xx：请求一个不存在的模型名 / 非法参数
    —— **未复现**：实测 404（坏模型）/ 400（非法参数），无 5xx
  - 断连：流式进行到一半 `AbortController.abort()`
    —— 已复现：200 + 58 个事件后 `Error: client-cancel`
  - 超时：分别测**首字节超时**与**总时长超时**（两者要分开设置）
    —— 已复现：首字节超时无状态码；总时长超时 200 + 182 个事件后切断
- [x] 每类故障记录：HTTP 状态码、响应体结构、是否发生在 SSE 流中途、错误格式是否与非流式一致
- [x] 关键观察：**错误可能以 SSE event 形式出现在流中间**（不是 HTTP 4xx/5xx），此时连接是 200
  —— 真实网关未复现；用本地 mock 补了两个变体
- [x] 把 4 个样本脱敏后存到 `notes/error-samples/`（实际 11 份 + `index.json`）

**验收**

- [x] 4 个样本齐全，每个都标注"连接层失败 / 应用层失败"
- [x] 能回答："200 + 流中途错误 event" 这种形态，你的解析器会不会静默吞掉
  —— 会，两个变体都不报错；证据见 `stream-error-mock-*.json`
- [x] 给出一份重试判定表：哪些可重试、哪些立即失败、哪些需人工介入（`devlog.md` Day 6 第 6 节）
